# アプリを閉じていても届く通知（Railway）の設定

所要時間は10〜15分です。作業は3つあります。

```
アプリ（ログイン中） ──通知の一覧・端末の宛先──▶ Firestore ◀──見張る── Railway のサーバー（server/）
                                                                         │ 時刻が来たら
iPhone / ブラウザ ◀──────────────── Web プッシュ ───────────────────────┘
```

## 1. Firebase の「秘密鍵」を作る

1. [Firebase コンソール](https://console.firebase.google.com/) で **schedule-list-7f9d8** を開く
2. 左上の歯車 → **プロジェクトの設定** → 上のタブ **サービス アカウント**
3. **新しい秘密鍵を生成** → **キーを生成** を押すと、JSON ファイルがダウンロードされる

> この JSON はサーバーの「合鍵」です。GitHub に上げたり、チャットに貼ったりしないでください。

## 2. Firestore のルールを更新する

1. Firebase コンソールの左メニュー **Firestore Database** → 上のタブ **ルール**
2. 中身をすべて消して、このリポジトリの [`firestore.rules`](../firestore.rules) の内容を貼り付ける
3. **公開** を押す

（追加されたのは `public/` を読めるようにする部分だけです。自分のデータを自分だけが読み書きできる点は変わりません）

## 3. Railway にサーバーを置く

1. [Railway](https://railway.com/) にログイン → **New Project** → **Deploy from GitHub repo**
2. **kami2news/schedule-check** を選ぶ（初回は GitHub との連携を許可）
3. できたサービスを開き **Settings** タブ
   - **Root Directory** に `/server` と入れる
4. **Variables** タブ → **New Variable**
   - 名前: `FIREBASE_SERVICE_ACCOUNT`
   - 値: 手順1でダウンロードした JSON ファイルを**テキストエディタで開き、中身をすべて**貼り付ける
5. 右上の **Deploy**（または自動で再デプロイされる）
6. **Deployments** → 最新のもの → **View Logs** に `通知サーバーを起動しました` と出れば成功

GitHub の `main` に変更を push すると、Railway も自動で更新されます。

## 4. 端末で受け取る

- **iPhone**: Safari でアプリを開く → 共有ボタン → **ホーム画面に追加** → ホーム画面のアイコンから開く
  （iOS 16.4 以降。Safari のタブのままでは受け取れません）
- アプリでログイン → 右上の人のアイコン → **この端末で受け取る** → 通知を **許可**
- **テスト通知** を押して、数秒で届けば完了

あとは予定・タスクの編集画面の「通知」で時刻を選ぶだけです。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「通知サーバーの準備ができていません」 | Railway のログに起動メッセージが出ているか／手順2のルールを公開したか |
| ログに `FIREBASE_SERVICE_ACCOUNT が設定されていません` | 手順3-4 の変数名・値 |
| テスト通知が届かない | iPhone: 設定 → 通知 → スケジュール が許可になっているか、集中モード中でないか |
| iPhone に「この端末で受け取る」が出ない | ホーム画面のアイコンから開いているか |

## 補足

- サーバーは1分ごとに確認するので、最大1分ほど遅れることがあります。サーバーが止まっていた場合、再開したときに直近10分の分だけ送ります。
- サーバーが送れるのは、**ログインして同期している予定**だけです。通知の一覧はアプリを開いたときに30日先まで作るので、ひと月以上アプリを開かないと、それより先の繰り返しの予定の通知は届きません。
- 状態の確認: Railway の **Settings → Networking → Generate Domain** で URL を作って開くと、送信数などが見られます（予定の中身は出ません）。
- 費用: 1分ごとに確認するだけの小さなプログラムなので、Railway の利用量はごくわずかです。Firestore の読み書きも無料枠に収まります。
